# Thickener Digital Twin (Project 4)

Physics-based thickener simulator and digital twin built from **Simulation and AI Modeling Projects for Mineral Processing — Project 4 (§5.6 and §5.8)** using **Python, FastAPI, NumPy, SciPy, pandas, HTML, CSS, vanilla JavaScript, and Plotly.js**.

> **IMPORTANT — SYNTHETIC DATA & ASSUMED PARAMETERS**
> No measured Project 4 plant dataset was supplied. Every synthetic record generated by this repository is explicitly labelled `SYNTHETIC`, overflow clarity is an `UNCALIBRATED_SYNTHETIC_PROXY`, and equipment/rheology/settling parameters in [`backend/config/model_parameters.yaml`](backend/config/model_parameters.yaml) are configurable engineering defaults—**never** present outputs as measured plant data.

---

## 1. Key Capabilities & Six-Page Web Application

| Page | Path | Functionality |
|---|---|---|
| 1. Dashboard | `/` (`index.html`) | KPI cards (feed rate, feed solids, predicted underflow solids, bed level, overflow clarity proxy, pumpability status), warnings, area & pressure breakdown, synthetic dataset preview |
| 2. Settling Flux Analysis | `/pages/flux.html` | Richardson–Zaki $v(\phi)$ & solids flux $F(\phi)$ curves, $F_{\lim}$ peak marker, exponential vs power-law flocculant comparison, required vs installed area |
| 3. Dynamic Simulation | `/pages/dynamics.html` | SciPy `solve_ivp` solids-inventory ODE & lagged compaction response to feed, withdrawal, and flocculant step changes + mass-balance closure check |
| 4. Pumpability Analysis | `/pages/pumpability.html` | Synthetic Bingham yield-stress curve $\tau_y(\phi)$, pipeline friction + static head pressure vs PD pump rating, max pumpable % solids |
| 5. Monte Carlo Analysis | `/pages/monte_carlo.html` | Seeded Monte Carlo trials across feed & settling CVs; Mean, SD, P5/P95, pumpability violation probability |
| 6. Scenario Analysis | `/pages/scenario.html` | Baseline vs modified comparison (preloaded for +20% feed / −50% flocculant dose) with deltas and calibration-range warnings |

## 2. REST API Endpoints

- `GET /api/health` — Backend health & data provenance status
- `GET /api/config` — Full YAML parameter register with units and status tags
- `GET /api/dataset/summary` — Synthetic dataset metadata & preview rows
- `POST /api/simulate` — Current thickener operating evaluation
- `POST /api/flux` — Settling velocity, flux curves, limiting flux, and dose comparisons
- `POST /api/dynamics` — Time-series ODE bed-level simulation
- `POST /api/pumpability` — Yield stress, required pressure, pumpability flag, and curve
- `POST /api/monte-carlo` — Uncertainty distribution and summary statistics
- `POST /api/scenario` — Baseline vs modified operating comparison

## 3. Local Setup & Running

```bash
cd thickener_digital_twin
pip install -r requirements.txt
python -m backend.data_generator
python -m backend.data_audit
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```
Open `http://localhost:8000` in your browser.

Run tests:
```bash
python -m pytest tests/ -v
```

## 4. Deploying on Render

Both a root [`../render.yaml`](../render.yaml) (using `rootDir: thickener_digital_twin`) and a standalone [`render.yaml`](render.yaml) + [`Procfile`](Procfile) are included.

1. Push this repository to GitHub/GitLab.
2. In Render, choose **New + -> Blueprint** (auto-reads `render.yaml`) or create a **Web Service** with:
   - **Root Directory**: `thickener_digital_twin` (if deploying from parent repo)
   - **Build Command**: `pip install -r requirements.txt && python -m backend.data_generator && python -m backend.data_audit`
   - **Start Command**: `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`
   - **Health Check Path**: `/api/health`
3. FastAPI serves both the `/api/*` endpoints and the static HTML/CSS/JS frontend on `$PORT`.

## 5. Parameter Register & Model Limitations

All defaults reside in [`backend/config/model_parameters.yaml`](backend/config/model_parameters.yaml):
- **Reference Ranges (Source Brief)**: Feed solids `4–15 % w/w`, Flocculant dose `10–40 g/t`, Underflow solids `55–70 % w/w`.
- **Assumed Physical & Settling Defaults**: Solids density `3200 kg/m³`, Liquid density `1000 kg/m³`, Free settling velocity `v0 = 7.0 m/h`, Richardson–Zaki `n = 4.65`, Thickener area `250 m²`, Depth `4.5 m`, Bed average solids `45 % w/w`, Bed compaction lag `1.5 h`.
- **Assumed Rheology & Pipeline Defaults**: Synthetic yield stress $\tau_y = 0.055 \exp(21.3 \phi)$ Pa, Plastic viscosity `0.08 Pa·s`, Pipe `300 m × 0.20 m`, Static lift `15 m`, Available PD pump pressure `15 bar`.

### Limitations & Data Required for Plant Calibration
1. **Unvalidated Physics Parameters**: $v_0$, $n$, flocculant dose-response coefficients, compaction sensitivities, and Bingham rheology parameters are synthetic defaults until batch-settling tests and rheograms are supplied.
2. **Uncalibrated Overflow Clarity**: `overflow_clarity_index` (0–100) is a heuristic proxy; calibrate against measured overflow turbidity (NTU) or TSS (mg/L).
3. **1-D Lumped Bed Balance**: Dynamic bed model assumes uniform cross-sectional bed solids concentration (`bed_average_solids_wt_pct`) and first-order underflow compaction lag (`bed_time_constant_h`).
4. **Required Plant Calibration Data**: Batch-settling curves at varied feed % solids and flocculant doses, achieved underflow density, overflow TSS/turbidity, mass flowrates, tank dimensions, bed-level logs, slurry/solids densities, rheograms, and pump/pipeline specs.
